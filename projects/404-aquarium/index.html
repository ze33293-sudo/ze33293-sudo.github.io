关键案例

同一输入，重建同一条鱼

机制示意：完整输入经统一处理后决定外观，分享参数用于在另一浏览器重建同一结果。

  1. 01

    整理输入

    去除首尾空白，必要时补协议，以完整字符串参与计算。

  2. 02

    确定外观

    哈希与样式规则决定体型、颜色、尾鳍等属性。

  3. 03

    本地收藏

    将生成结果保存在当前浏览器的收藏中。

  4. 04

    分享重建

    通过链接中的 fish 参数，在目标浏览器重建同一结果。

适用范围不检测真实 404；分享参数含可还原输入，收藏仅在本浏览器。已有构建与渲染记录，完整交互仍待验收。

1. 项目概览与核心价值

以用户输入的 URL 为种子，我设计了数字鱼生成、收藏证书和分享原型。生成规则对处理后的完整字符串计算哈希，同一输入对应稳定形象；产品不访问原链接，也不判断页面是否真实返回 404。

项目尝试为失效链接提供可保存、可分享的互动结果。确定性生成让用户再次输入或分享同一地址时能够重建相同的鱼，收藏兴趣与分享意愿仍需用户测试。

2. 项目背景和机会判断

“失效链接变成数字鱼”是创意假设。首版先验证同一输入能否得到稳定形象，以及生成、收藏、分享的流程是否成立；暂不加入真实链接检测、账号、服务端数据库或模型生成。

3. 目标用户、使用场景与现有流程

潜在用户是喜欢数字收藏和轻量互动的人；当前尚未通过用户访谈验证，也未作为真实网站的 404 页面投入使用。

我设想的场景是：用户从旧收藏夹、失效文章或朋友分享中得到一个地址，在本产品中粘贴地址、生成数字鱼、查看证书，再决定收藏或分享。下一步需要观察用户是否愿意走完这条流程，以及收藏和分享分别有什么吸引力。

4. 需求与优先级

P0 是同一 URL 的生成结果必须稳定。

P0 是系统不能为了验证地址而访问用户提交的 URL。

P1 是生成结果具有足够差异，用户能理解 URL 特征如何影响鱼。

P1 是收藏和分享流程完整。

P1 是持续动画具有暂停或减弱方式，并为 Canvas 提供语义化信息。

P2 是增加更多物种、彩蛋和收藏玩法。

5. 目标与验收标准

功能验收围绕生成、收藏和分享三个动作：同一处理后输入应产生一致形象；在同一浏览器打开同一网站并刷新后，收藏应保留；打开分享链接应能重建同一条鱼。这些行为仍需完成浏览器交互验收。

输入为空时应提示；生成过程不访问原地址；证书和操作状态应能通过文字读取，并响应减少动画偏好。当前输入处理仅包括去首尾空白和补协议，严格格式校验尚待补充。

用户价值与功能验收分开检查：后续观察用户能否独立完成生成，以及是否主动收藏或分享。当前没有这些用户行为的统计结果。

6. 我的职责与协作边界

我比较随机生成、图像模型与确定性规则，选择规则生成以保持形象一致；设计生成、收藏与分享流程，以同一输入结果一致、分享后可重建作为验收标准。

这是独立创意原型，没有真实客户或运营团队。项目中的“生成”由确定性程序规则完成，没有调用生成式模型。这个选择本身体现了我的产品判断：可解释、低成本和可复现更符合该体验的核心需求。

7. 调研、替代方案与范围取舍

我比较了三种生成方式：每次随机生成、调用图像模型生成、依据 URL 确定性生成。随机方案缺少收藏身份，模型方案会增加等待、费用和内容一致性问题。最终采用哈希种子与程序化绘制。

首版使用 localStorage 保存收藏，不引入账号或数据库。分享链接携带可还原的原始输入，用它重建数字鱼；因此分享不具备匿名化效果，不适合含令牌、个人信息或内部路径的地址。

8. 方案与使用流程

用户输入后，程序去除首尾空白并在需要时补协议；空输入会提示。当前生成流程不阻止所有非法 URL，处理后的完整字符串直接用于计算哈希。

完整字符串的哈希决定体型、主辅色、尾鳍、纹理、速度和稀有度；.edu、.gov、#、love、localhost 等字符串触发额外样式。外观由完整输入共同决定，而非逐字段独立映射。

Canvas 根据这些参数绘制并驱动水族馆动画。生成后，系统展示结构化证书，用户可以收藏、移除或复制分享链接。分享链接中的 fish 参数在目标浏览器重新构造同一结果。

9. 三项关键决策及其权衡

第一，采用确定性生成。

它让数字鱼拥有稳定身份，也让规则可解释；代价是同一个 URL 不会产生无限随机变体。

第二，生成计算在浏览器完成，不请求原地址，收藏保存在本浏览器。

代价是清理数据或更换浏览器会影响收藏；分享链接还会暴露所携带的原始输入，需要单独说明。

第三，使用 Canvas 承担视觉表现，同时用普通 HTML 提供鱼的名称、属性、状态和操作。

这样兼顾动态效果和辅助技术可读性，但需要维护视觉层与语义层的一致性。

10. AI、规则与人工分工

本项目没有将大模型放入运行链路。哈希规则负责生成稳定参数，Canvas 负责图形与动画，浏览器存储负责收藏，剪贴板 API 负责分享。

人工负责命名词库、稀有度规则和不同输入的视觉检查；是否具有收藏吸引力仍需邀请用户实际体验。

11. 数据与技术方案

产品采用前端单页结构，输入先去除首尾空白并按需补协议，再经过字符串哈希、参数映射和 Canvas 绘制。收藏以 JSON 存入 localStorage，分享信息放入页面查询参数。

系统没有账号、云数据库、远程 URL 校验和 API 密钥。Canvas 只负责可视化，页面另外提供 ARIA 标签、状态提示、按钮按压状态和证书文本。动画响应 prefers-reduced-motion 偏好。

12. 评测与案例复盘

已有生产构建和渲染后 HTML 检查记录，检查页面响应、标题及固定文案。这些检查说明页面可构建与渲染，不代表生成、收藏和分享已经通过浏览器交互验收。

已有异常处理及待补验收场景包括：

空输入会提示；缺少协议时自动补全。非法格式的严格校验与修正指引尚待补充；

读取收藏时捕获损坏 JSON，忽略异常记录后继续初始化；写入失败的提示与回退尚未覆盖；

剪贴板权限被拒绝时，应展示可手动复制的链接；

清理浏览器数据会丢失本地收藏；应补充存储边界提示，并检查隐私模式下的表现；

已响应系统减少动画偏好，独立暂停按钮和完整无障碍检查仍待补充。

13. 风险与异常处理

生成过程不请求用户提交的原始地址。分享链接的 fish 参数包含可还原的原始输入，接收者能够查看，打开分享链接也会将参数带入本站请求；不能把本地生成概括为全流程不传输原地址。

读取损坏的收藏数据时回到默认初始化；复制分享链接失败时展示手动复制文本；减少动画模式保留静态画面。存储写入失败、严格输入校验和敏感分享提醒仍属待完善项。

14. 成果与验证范围

本阶段完成字符串种子生成、Canvas 展示、本地收藏与分享链接，已有生产构建和渲染后 HTML 检查记录。已处理损坏收藏读取、剪贴板失败和减少动画偏好；这些记录不替代完整浏览器交互验收。

尚未验证的是用户对收藏体系的长期兴趣、分享传播率、不同设备性能和大规模鱼群渲染。可拓展方向包括浏览器扩展、网站 404 组件、主题鱼池和收藏图鉴，但这些仍属于下一阶段假设。

15. 项目复盘与下一步

确定性规则回应了收藏与分享需要稳定身份的要求，但这种一致性不能说明用户会喜欢或愿意收藏。下一步需要分别验证操作是否顺畅，以及数字鱼本身是否有吸引力。

先补充严格输入校验、收藏写入失败和敏感分享提醒，并完成跨浏览器操作检查；再邀请用户独立尝试生成、收藏和分享，记录需要解释的步骤、放弃的位置，以及收藏或分享的原因，据此决定是否增加更多玩法。
