1. 业务背景与用户问题

本地模型如果直接获得文件系统权限，会把模型判断错误扩大成真实写入或路径越权。

模型只能通过受限工具读取授权工作区；所有写入逐次确认；Agent 循环有明确预算。

2. 我的角色与职责边界

实现最小 Agent 循环，拆分模型判断与 Python 执行，并验证路径穿越、绝对路径和写入确认。

没有 Web UI、多 Agent、云端沙箱或无人值守长期运行；本地运行数据当前为空。

3. 方案与端到端工作流

接收用户目标

模型选择受限工具

Python 校验路径与权限

人工确认写入

工具结果返回模型继续判断

4. 关键决策与取舍

模型没有直接文件权限

工具开发成本增加，换取执行边界可测试。

所有读写都经过工作区解析与路径检查。

写入逐次确认

交互更慢，但高影响动作保持可见和可取消。

保存笔记和长期记忆前显示具体参数。

循环最多八轮

复杂任务可能提前停止，避免工具调用失控。

Agent 运行时包含固定循环预算。

5. 权限、人工介入与失败降级

读取授权目录、分析文本和返回工具结果。

保存笔记与长期记忆等所有写入动作。

超过循环预算、路径越界或工具异常时停止执行并返回错误。

6. 评测、Bad Case 与迭代

归档测试和真实工具调用通过。

7. 业务价值与证据
